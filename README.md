# RustFix by yawaside

RustFix - настоящее **портативное приложение Windows x64** на .NET 8 WPF.
Релиз содержит **один автономный `RustFix.exe`**: не нужны браузер,
`.cmd`, `.ps1`, установщик или отдельная установка .NET Desktop Runtime.

Заданная пользователем сборка для сравнения: **Windows 11 24H2 / 26100.8894**.
Канал: https://t.me/TriagedRust

## Скачать и использовать

1. Откройте **Releases** в этом репозитории. Скачайте `RustFix.exe` из нового
   релиза (v1.5.1 или новее).
2. Запустите EXE двойным щелчком и подтвердите UAC. Для работы с обновлениями
   нужны права администратора. Неподписанный файл может вызвать предупреждение
   SmartScreen.
3. Приложение **само** читает сборку (`CurrentBuildNumber` и `UBR`) из реестра
   и сканирует установленное через `Get-HotFix` и `Get-WindowsPackage` (CBS).
   Последний источник показывает и пакеты, которых нет в обычном списке KB.
   Ничего вручную вводить не нужно.
4. Отметьте конкретные **допустимые для попытки удаления** пакеты и подтвердите
   действие. Системные/защищённые компоненты видны, но не выбираются. Утилита
   сначала попробует создать точку восстановления; при неудаче потребуется
   ваше отдельное согласие на продолжение. Для CBS применяется DISM с **точным
   именем пакета**, при наличии KB возможна попытка через WUSA.
5. Посмотрите результат и коды ошибок, затем при необходимости перезагрузите
   ПК и нажмите «Обновить список». Пауза и политики - в «Настройках».

**Невозможно гарантировать снятие любого пакета Windows.** Постоянные пакеты
и обновления стека обслуживания Windows может не позволить удалить. RustFix
не редактирует манифесты CBS, не удаляет `pending.xml` и не выполняет
`DISM /ResetBase`: это лишило бы систему возможности отката. Перед любыми
изменениями создайте резервную копию важных данных.

Ссылка в настройках ведёт на официальную страницу загрузки Windows 11, но
**не гарантирует ISO именно сборки 26100.8894**. Проверьте версию образа перед
переустановкой.

## Релиз EXE на GitHub

Единственный релизный workflow: `.github/workflows/build-exe.yml`.
Старый ZIP/Edge workflow удалён: он публиковал ZIP вместо EXE.

Способ 1 - запушьте код, затем **новый** тег:

```bash
git add .
git commit -m "Release native RustFix"
git push origin main
git tag v1.5.1
git push origin v1.5.1
```

Способ 2 - **Actions -> Build RustFix.exe -> Run workflow**. Выберите ветку с
этим кодом и укажите **новый тег** `v1.5.1` в поле `release_tag`. Ручной запуск
тоже создаст Release с EXE.

Workflow на `windows-latest` собирает проект `src-exe/RustFix.csproj` через
`dotnet publish`, затем **проверяет**: в папке публикации ровно один файл
`RustFix.exe`, он имеет сигнатуру Windows PE (`MZ`). После проверки EXE
загружается и в артефакты Actions, и в Releases. Пустой asset вызывает ошибку.

**Важно:** старый тег - это снимок старого коммита. Если `v1.5.0` уже был
запушен со старым workflow, обычный push в `main` его не обновит. Сделайте
`v1.5.1` (или более новый тег) после загрузки исправлений.

### Локальная сборка на Windows

Требуется .NET 8 SDK:

```powershell
dotnet publish .\src-exe\RustFix.csproj -c Release -r win-x64 --self-contained true -o .\dist-exe
```

Результат: `dist-exe\RustFix.exe`. Автономный WPF EXE включает среду .NET,
поэтому весит больше скрипта. При первом запуске native-компоненты .NET
распаковываются в `%TEMP%\.net`; установщик не запускается.

## Веб-превью

`src/App.tsx` - **демо с примерными данными**, а не сканер компьютера.
Браузер не может прочитать обновления Windows или удалить их. Кнопка
скачивания ведёт на `RustFix.exe` в Releases, если задать при сборке сайта
`VITE_GITHUB_REPOSITORY=owner/repo`; на GitHub Pages путь проекта определяется
автоматически. Без адреса репозитория сайт показывает инструкцию вместо
ложной ссылки на `.cmd/.ps1`.
